# Native model execution

The standard CORE-AI worker stays unchanged. Native Superpowers, Ponytail and combined profiles are optional Tools-mode agent capabilities, not mandatory dependencies. They execute in fresh OpenCode containers without host workspace, Docker socket, credentials or external network. A temporary Unix socket bridges only the administrator-approved local Ollama model's inventory, show and chat-completions routes. Source/image/model digest and exact mode are rechecked before every call. No package is fetched during execution. Each run starts one private server and waits for the exact OpenCode version, active native plugins, their complete skill inventories and the selected Ollama model before attaching the CLI.

## Operator qualification

Use the same private IPv4 endpoint and model name already configured in CORE-AI Models. The model must be locally installed, advertise completion and tools, and not be an Ollama cloud model. Run on the Ubuntu lab owner account during an idle model window. Example (substitute actual configured values):

    python3 lab/native_execution.py review superpowers --endpoint http://10.8.0.2:11434 --model qwen3:4b
    python3 lab/native_execution.py qualify superpowers --endpoint http://10.8.0.2:11434 --model qwen3:4b --approve REVIEWED_DIGEST

Repeat for ponytail and combined; default mode is full. Ponytail and combined also accept --mode lite or --mode ultra, on both review and qualify. Each model/mode needs its own qualification. Standard execution is the off alternative. A registration receipt alone is not model qualification. Superpowers requires an observed completed brainstorming skill tool call; Ponytail requires a completed ponytail-review skill call and the upstream mode marker in the actual system message forwarded to Ollama; combined requires both skill calls and the hook. A failed or timed-out fixture is not a qualification. No raw prompts or model responses are stored in qualification receipts.

    python3 lab/native_execution.py status

After qualification, deploy through the existing lab/install-integration.sh --approve-deploy workflow (review first), with both checkouts on the same release. The Tools catalog shows native model qualification records separately from registration. Agent settings and Agent Team Builder expose native.superpowers, native.ponytail and native.combined. Select Tools mode, an exact qualified local model, and one or more explicit native capabilities. In a project task ask the agent to delegate a bounded design/review problem to the permitted native tool, mode full unless another mode was qualified. Check task step history for native-opencode provenance, model calls, skill evidence, and qualification ID. Use the same agent in manual or reviewed master-planned missions. The master planner itself stays analysis-only. Native delegation from external connection tasks or Chat is not enabled by this release. No automatic deployment, repository edits, or host file access.

Native execution defaults to a 540-second isolated run, a 300-second upstream socket inactivity timeout, and 16 model calls, 2 GiB container memory, and existing shared gateway slot. Parent cancellation is reconciled after the bounded native call returns; no guarantee that Ollama stops immediately. A nested native run may require more time than a basic task; choose an adequate task budget. Native tools are unavailable if no current matching receipt is found. A recorded receipt is historical evidence, not a live health check. This implementation must still be qualified against the actual server's OpenCode/Ollama and user-selected model; CI fixtures do not establish real inference or autonomous workflows.

The operator may set CORE_AI_NATIVE_TASK_SECONDS (180–540) and CORE_AI_NATIVE_INFERENCE_SECONDS (30–300), with at least 60 seconds between the two limits. Both are included in the approved plan: review and qualify again after changing either. If using overrides, the lab gateway must use the same values as the qualification shell. The parent gateway client allows 720 seconds for native calls including review and cleanup. The parent task still needs adequate execution-policy budget; cancellation is reconciled on return. A timeout returns a classified 504 before streaming starts, upstream HTTP rejection a 502, and invalid requests retain 422. A stream already started cannot change its HTTP status; a bounded, sanitized failure category is included in CLI failure diagnostics. No raw upstream error body or request is logged. These limits are not a guarantee of completion on a slow host.
